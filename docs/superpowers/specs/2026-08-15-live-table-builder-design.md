# Live Table Builder — Design

## Goal

Add a second browser-only page for visually composing GitHub-compatible Markdown tables with any number of rows and columns. Each cell may contain text and multiple image or video assets, while the generated Markdown updates live in a result panel.

## Scope

- Add `builder.html` and link it with the existing normalizer page.
- Allow rows and columns to be added, renamed, reordered, and removed.
- Allow free text and multiple assets in every body cell.
- Accept GitHub attachment Markdown or URLs as export-ready assets.
- Accept pasted or dropped local image/video files for preview, but mark them unresolved until a GitHub URL is supplied.
- Keep all state in the current browser tab. Do not add authentication, persistence, a backend, or undocumented GitHub uploads.

## Navigation and Page Layout

Both pages use a compact navigation with **Normalizer** and **Table Builder** links. `builder.html` contains:

1. A concise page introduction explaining the GitHub attachment workflow.
2. A toolbar with **Add column** and **Add row** controls.
3. A horizontally scrollable live table editor.
4. A validation summary for unresolved local assets.
5. A read-only **Hasil Normalisasi** Markdown textarea with a copy button.

The initial table has three named columns and two editable body rows. The layout remains usable on mobile through horizontal table scrolling rather than squeezing cells too narrowly.

## Table Model

State is represented independently from the DOM:

```js
{
  columns: [{ id, label }],
  rows: [{ id, cells: { [columnId]: { text, assets: [] } } }]
}
```

Each asset has a stable ID, kind (`image` or `video`), source type (`github` or `local`), display name, preview URL, and export value. GitHub assets contain an exportable URL or Markdown fragment. Local assets use an object URL only for preview and have no export value.

At least one column must remain. Rows may be reduced to zero and added again. When a column is removed, its cell content is removed after a confirmation if that column contains text or assets. Deleting a non-empty row also requires confirmation.

## Editing and Asset Workflow

Each body cell contains:

- A text area for Markdown-safe text.
- A drop zone that also supports choosing files.
- A list of asset preview cards with remove actions.

Supported local preview formats are PNG, GIF, JPEG, SVG, MP4, MOV, and WebM. Multiple files may be dropped or pasted into one cell. Unsupported files show a cell-level error and are not added.

Dropping or pasting a local file creates a preview card labelled **Needs GitHub URL**. The card provides an input where the user can paste the URL or full Markdown generated by a GitHub issue/comment draft. Once parsed successfully, the same card becomes a GitHub asset and is export-ready. There is no separate direct-add GitHub URL form in the cell; resolution happens only from an existing local asset card.

Object URLs are revoked when assets are removed, rows or columns are deleted, or the page unloads.

## GitHub Asset Parsing

The parser accepts:

- Markdown images: `![alt](https://github.com/user-attachments/assets/...)`
- HTML images using an absolute GitHub attachment URL.
- Absolute `https://github.com/user-attachments/assets/...` URLs.
- Absolute GitHub-hosted video attachment URLs or Markdown fragments generated by GitHub.

The parser preserves valid GitHub-generated Markdown fragments. A bare image URL is serialized as an HTML image with a conservative width attribute; a video URL is serialized as its bare GitHub attachment URL because GitHub renders uploaded media from its generated comment markup. Non-GitHub URLs are rejected in this first version to keep the export contract predictable.

## Markdown Serialization

The first table row contains escaped column labels and the second row contains `---` separators. Each body cell serializes content in this order:

1. Escaped text, with line breaks converted to `<br>`.
2. Export-ready assets in their visual order.

Items inside a cell are joined with `<br>`. Literal pipe characters in text are escaped as `\|`. Newlines cannot split a Markdown table row. Every generated row begins and ends with `|`, matching the normalizer output style.

Local unresolved assets are represented only in the editor, never as `blob:` or Base64 content in Markdown. While any unresolved asset exists, the output remains visible for inspection but the copy button is disabled and the validation summary tells the user how many assets still need GitHub URLs.

## Error Handling and Accessibility

- Reject unsupported file types and malformed/non-GitHub URLs with actionable cell-level errors.
- Confirm destructive removal only when content would be lost.
- Give row, column, cell, asset, and reorder controls explicit accessible labels.
- Support keyboard activation for file selection and all table actions.
- Use live regions for copy status and unresolved-asset summaries.
- Preserve visible focus states and reduced-motion preferences from the existing page.

## Code Boundaries

- `builder.html` owns semantic structure and static copy.
- `builder.css` owns builder-specific table, cell, asset-card, toolbar, and responsive styles while reusing the established visual language.
- `builder.js` contains pure state helpers, asset parsing, Markdown serialization, object-URL cleanup, and guarded DOM initialization.
- `script.js` remains focused on the existing normalizer.

## Verification

Node 12-compatible tests cover escaping, row/column mutations, multiple assets per cell, GitHub attachment parsing, Markdown serialization, and unresolved-asset detection. Static checks verify required page controls. Manual browser checks cover adding, renaming, reordering, and removing rows/columns; multi-file drop/paste previews; resolving local assets with GitHub URLs; copy gating; responsive scrolling; and keyboard interactions.

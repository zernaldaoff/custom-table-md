# Undo and Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add shared, button-driven and keyboard-accessible Undo/Redo history to both the Markdown Normalizer and Live Table Builder.

**Architecture:** A standalone `history.js` implements bounded generic snapshot history with no DOM dependency. Each page adapts its own serializable state into the manager, groups typing changes, restores UI from snapshots, and updates common Undo/Redo controls.

**Tech Stack:** Vanilla JavaScript, semantic HTML/CSS, Node.js 12 `assert` tests.

---

### Task 2: Build the generic history manager with TDD

**Files:**
- Create: `tests/history.test.js`
- Create: `history.js`

- [ ] **Step 1: Write failing history behavior tests**

Require `createHistory` and `getHistoryShortcut`. Assert:

```js
const history = createHistory({ value: 0 }, { limit: 3 });
history.commit({ value: 1 });
history.commit({ value: 2 });
assert.deepEqual(history.undo(), { value: 1 });
assert.deepEqual(history.redo(), { value: 2 });
```

Also test equivalent commits are ignored, `replace` groups changes without increasing the undo depth, a new commit after undo clears redo and calls `onDiscard`, the limit evicts the oldest snapshot, returned states are clones, subscribers receive capability changes, reset clears both stacks, and shortcut classification supports Cmd/Ctrl+Z, Cmd/Ctrl+Shift+Z, and Ctrl+Y.

- [ ] **Step 2: Run tests and verify RED**

Run `node tests/history.test.js`; expect failure with `Cannot find module '../history.js'`.

- [ ] **Step 3: Implement `createHistory`**

Implement a closure with `past`, `current`, `future`, `listeners`, `limit`, `clone`, `equals`, and `onDiscard`. Return:

```js
{ commit, replace, undo, redo, reset, getState, canUndo, canRedo, subscribe, dispose }
```

Every public state return is cloned. `commit` clears/discards future snapshots, pushes current into past, applies the limit, and notifies subscribers. `replace` discards only the replaced current snapshot. `dispose` discards every retained snapshot once and clears listeners.

- [ ] **Step 4: Implement shortcut classification**

`getHistoryShortcut(event)` returns `"undo"`, `"redo"`, or `null`; ignore events with Alt, require Ctrl or Meta, treat Shift+Z and Ctrl+Y as redo, and compare keys case-insensitively.

- [ ] **Step 5: Run GREEN verification and commit**

Run `node tests/history.test.js` and `node --check history.js`, expect zero failures/errors, then:

```bash
git add history.js tests/history.test.js
git commit -m "feat: add shared undo redo history"
```
